# 证据、指标与工程术语审查手册

本手册是写作审查协议，不是对项目的认证。规则用于限制结论，不要求所有项目都实现同一种底盘。

## 1. 一条简历主张需要多强的证据？

| 想写的主张 | 最低应确认的信息 | 不能直接升级成 |
|---|---|---|
| 实现某模块 | 本人修改范围、实现说明或代码位置 | 已通过测试、已生产上线 |
| 测试通过 | 测试命令/环境、执行结果、范围；或用户明确确认 | 全系统无缺陷 |
| 支持取消 | 取消检查位置、终止/屏蔽语义、已验证场景 | 取消外部 API 已发生的副作用 |
| 支持任务恢复 | 持久状态、恢复入口、重启后的继续执行记录 | 恰好一次执行 |
| 索引发布管控 | 版本写入、可见性切换、读侧过滤、失败处理 | 跨库强事务、零停机 |
| 指标变化 | 同口径版本、题集、样本量、数值与来源 | 确定的策略因果收益 |
| 稳定改进 | 适当对照、重复、变异性与失败运行处理 | 跨任务、跨模型均有效 |
| 生产可用 | 实际部署、负载/故障测试、权限与运维证据 | 行业通用的“生产级认证” |

证据类型与完成状态分开记录：来自用户口述的“已上线”仍是用户陈述，不自动变成助手读过生产日志。源码、README、测试和日志之间冲突时，不替用户裁定哪个版本是事实。

## 2. 系统指标

**状态与恢复。** HTTP/SSE 连接恢复是传输层行为；历史事件回放需要服务端留存事件和客户端游标；计算恢复需要持久状态与恢复执行逻辑。进一步保证副作用不重复，还需要与工具执行相关的幂等或去重设计。SSE 标准定义了重连与 Last-Event-ID，但不负责应用业务状态恢复。[来源 S4/S5](sources.md)

**租约与隔离。** “过期后不再续租”不等于“旧执行器不能写”。应问：旧任务暂停后恢复，会不会继续写？写入是否校验当前代次或版本？检查与提交是否存在竞争窗口？取消检查与结果发布是不是同一事务或有其他等价保护？本手册不要求一律使用 fencing token，只要求结论能由实际机制支持。

**双库一致性。** 按版本写入、读侧筛选、状态机发布、补偿与清理，都可以是实际方案；不能仅凭 MySQL + pgvector 推导原子提交。说明实际保证的是“读侧只见已发布版本”，还是“最终补齐”，不要笼统宣称“强一致”。

**系统观测。** Trace 应说明粒度、关联 ID、输入输出、版本、耗时与异常的实际记录范围；不要自动添加敏感原文留存。能查看轨迹是可观测能力；只有真实故障案例与修复后的检查，才构成修复回归闭环。

**可靠性分母。** 任务成功率要说明 task/turn/session 的单位，超时、取消、重试与外部工具失败如何处理。重试后成功与首次成功分别统计，避免成功重试掩盖额外成本。

**效率分母。** 时延给出端到端范围、是否包含排队/模型调用/重试、并发与样本量；若有 p50/p95 则分别报告。Token 指标明确输入、输出、检索改写、评审、工具调用是否包含；无计价口径，不将 tokens 下降换成费用下降。

### 将评测写成量化成果

有评测记录时，正文必须呈现指标值与范围，不能停留在“搭建评测体系”。先选与问题直接相关的效果指标，再附已有的延迟或成本代价。记录缺失时注明未测，不补数。

下表是**完全假设的格式演示**，含 200 题规模在内均不是本仓库或用户的成绩；假设各项有效 N 均为 200、同题同预算且费用口径一致。

| 维度 | 指标 | 基线 | 当前 | 正确变化表达 |
|---|---|---:|---:|---|
| 检索 | Recall@10 | 0.72 | 0.89 | +0.17，或 +17 个百分点 |
| 忠实度 | Faithfulness 平均分 | 0.81 | 0.91 | +0.10 分；不叫答案准确率 |
| 延迟 | 端到端 P95 | 1600 ms | 1720 ms | +120 ms |
| 成本 | 每题费用 | 0.0100 元 | 0.0108 元 | +8% |

可写为“在该示例集上，检索 Recall@10 由 0.72 到 0.89，忠实度平均分由 0.81 到 0.91；代价是 P95 增加 120 ms、每题费用增加 8%”。所有值必须由真实记录替换。质量有增益但成本上升时，两者一起保留；若结果无增益，写实际差异与工程决策。

## 3. RAG / Agent 指标

### 3.1 检索与拒答

对单题 q，若存在完整相关证据集合 Rq：

```text
Recall@k(q) = |TopK(q) ∩ Rq| / |Rq|
Hit@k(q)    = 1[TopK(q) ∩ Rq 非空]
```

没有完整相关证据标注时，承认只计算命中率或近似代理指标；说明文档级还是分块级、父子块如何去重，以及无相关证据题如何处理。不能把两个定义混着报。

拒答至少区分两个标签轴：

| 真值 / 系统行为 | 作答 | 拒答 |
|---|---|---|
| 应答 | 还需判定回答是否正确 | 错误拒答 |
| 应拒 | 不当作答 | 正确拒答 |

```text
拒答率 = 拒答数 / 全部评测样本数
错误拒答率 = 应答但拒答数 / 应答样本数
正确拒答率（应拒集）= 应拒且拒答数 / 应拒样本数
拒答决策准确率 = 正确的作答/拒答决策数 / 全部评测样本数
```

“拒答准确率”有歧义，必须说明使用的是哪个分母。即使拒答决策正确，作答内容也可能错误。总体拒答率由 71.7% 变为 56.5%，只说明拒答比例减少约 15.2 个百分点；没有标签分解，不能推出“无理由拒答减少”。这是逻辑约束，不依赖某一种评审工具。

引用覆盖率、引用正确率、忠实度与答案正确率分开写：引用存在，不意味着它支持论断；忠于错误证据，也不意味着答案事实正确。

### 3.2 对话与 AI 审阅

多轮任务优先按会话划分数据；不要将同一会话相邻轮分别放进训练与测试。测试集存在共享文档时说明评估目的，不机械认定所有文档共享均为泄漏。

AI 审阅记录模型/版本、提示词、判分规则、重复方式及冲突处理。AI 审阅与人工复核是不同证据；不得凭“AI 盲审”宣称人工金标。只有预先构造了标注答案/证据并确认质量时，才写相应金标名称。

压缩记忆的评价需要同一对话任务、评价准则、压缩前基线和完整 token 口径。“摘要更短”不足以说明一致性没有下降。

## 4. 实验设计与比较强度

| 实际做法 | 可以写 | 不能写 |
|---|---|---|
| 一次运行无基线 | 已完成一次评测，或在内部保留绝对观测值 | 提升、优于、优化收益 |
| 两个版本、同一题集、各一次 | 在该题集与条件下观察到差异 | 已排除 LLM 随机性 |
| 两次运行的事后共同题交集 | 在共同题交集上进行回顾性比较 | 预先冻结的独立测试集 |
| 逐步增加 A/B/C 模块 | 当前累积组合下的条件增量 | 各模块独立贡献、无交互作用 |
| 每次只改一个因素 | 在其余明确条件下的受控对照 | 自动推广到任何模型和预算 |
| 多随机种子/重复运行 | 描述均值、离散性及比较范围 | 仅挑最好的一次 |

配对是“相同评估单元被两个方案共同测量”，不是“两个数放在一起”。没有逐题映射或同一统计单元，不声称配对。

训练种子、推理采样和 AI 评审是不同随机来源。200 道题 × 每题 8 次生成，不等于 1600 个独立问题；对话中相邻轮也不是完全独立样本。置信区间与检验应采用适合统计单位的方法；没有实际计算就不添加误差条、p 值或显著性。

所有失败运行、超时、未评分项及排除规则应留档。共同题数量与完整评测题数同时保留；不得悄悄换分母。算法失败是结果，基础设施故障的重跑也需要对各组使用同一规则。

## 5. 后训练 / GRPO / RLVR

### 5.1 最低配置卡

记录基座与修订、SFT/初始 checkpoint、LoRA 配置（确实使用时）、训练数据版本及去重、分割、奖励函数及解析器版本、组大小、最大长度、解码、优化器、学习率、batch/累积、更新步数、checkpoint 选择规则、训练随机种子、硬件和精度。不是所有字段都进简历，但所有会改变比较结论的字段都应能追溯。

“自实现”说明具体范围：rollout 管理、优势计算、loss、更新循环等；不要求重写自动微分和模型加载。直接使用现成 RL Trainer 时，写配置、组件修改和评测贡献。

### 5.2 DAPO 语义

DAPO 参考论文讨论 Clip-Higher、Dynamic Sampling、Token-Level Policy Gradient Loss 和 Overlong Reward Shaping，也明确去掉了其算法的 KL 惩罚项。复现变体若仍保留 KL，需要说清楚；**记录 KL 作为监控，与把 KL 纳入训练目标完全不同**。[来源 S6](sources.md)

Dynamic Sampling 会筛选组内无有效相对信号的样本，因此要同时记录有效组比例、生成样本/总 tokens、丢弃比例与计算时间。不能把更新步数降低直接转述成等比例成本降低。[来源 S6](sources.md)

“组内零方差比例”需定义是奖励还是优势、按 prompt-group 还是轨迹统计、筛选前还是后；否则动态筛选后的低比例可能只是定义结果，而不是模型探索改善的证据。

熵、KL、长度曲线是诊断信号；需明确估计方式、mask、聚合与观察窗口。仅有曲线不足以证明崩塌根因，尤其不能把某个熵数值当作跨模型通用阈值。

### 5.3 pass@k 与效率

对每道题生成 n 个候选，其中 c 个通过验证，常用估计为：

```text
pass@k = 1 - C(n-c, k) / C(n, k)  （n ≥ k；n-c < k 时为 1）
```

再按题平均；k=1 时是 c/n 的逐题平均，k=n 时是“本组至少一次成功”的指示值。这与多数投票、挑最高 reward 的 best-of-n、单次贪心准确率不同。原始实现可参考 OpenAI HumanEval；将该定义用于数学题时，还须说明答案等价核验器。[来源 S7](sources.md)

预算应区分等更新步数、等生成 tokens、等 GPU-hours 和达到同一质量阈值。等步数的结果可以报告，但不能称等算力。达到阈值所需步数的比较应在开发集预先定义阈值，不用测试集反复选择 checkpoint。

## 6. 写作完成后的放行规则

出现任何伪造、错归属、分母不明却声称收益、观察越权成为因果、未运行冒充已运行：不放行为终稿。诚实但证据稀疏：允许按当前阶段写作，列出最关键缺口，不把未来工作加进经历。

工程成熟度不是术语竞赛。固定工作流可以是合理解法；多节点不等于多 Agent，自主决策也不由“Agent”命名自动证明。具体机制比复杂标签更可检验。[来源 S8](sources.md)
